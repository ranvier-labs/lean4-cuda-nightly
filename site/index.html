Lean CUDA

Compiles ordinary Lean declarations to CUDA. Control flow, tiling, synchronization, and ownership stay in Lean. C++ is only instruction-sized shims that CUDA C++ cannot write directly.

A kernel is a Lean definition

Mark a Cuda.DeviceM function with @[cuda_kernel]. The compiler emits a CUDA translation unit and typed host companions: launch, attributes, occupancy. 

@[cuda_kernel]
def saxpy (params : SaxpyParams) (xs ys : Cuda.DeviceSlice Float32) :
    Cuda.DeviceM Unit := do
  let i := (← Cuda.blockIdxX) * (← Cuda.blockDimX) + (← Cuda.threadIdxX)
  if i.toUSize < xs.size then
    let x ← Cuda.loadFloat32 xs.ptr i.toUSize
    let y ← Cuda.loadFloat32 ys.ptr i.toUSize
    Cuda.storeFloat32 ys.ptr i.toUSize (params.a * x + y)

That is the SAXPY example from the companion example repository, verified bit-for-bit against host Float32 arithmetic.

What this is

Lean owns the kernel

Not a C++ kernel called from Lean. The LCNF pipeline lowers the marked declaration to CUDA C++.

A narrow launch ABI

Parameters are scalars, device pointers, Dim3, or address-free POD records. Host IO and tasks are rejected on device.

Shims, not a DSL dump

TMA, WGMMA, mbarrier, stmatrix, and register redistribution are force-inlined instruction shims.

Alpha, not upstream

The attributes, launch ABI, and Lake recipe will change. This is not an official Lean release.
